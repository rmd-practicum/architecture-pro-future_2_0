# Интеграция с CI/CD GitHub

## S3-бэкенд Terraform

Для хранения состояния Terraform при работе с GitHub CI/CD выбрано объектное хранилище Yandex Cloud.

В файле [backend.tf](./backend.tf) описан S3-совместимый бэкенд для Terraform на основе объектного хранилища Yandex Cloud. При деплое из CI/CD, этот файл копируется к основной конфигурации Terraform: такая реализация позволяет запускать скрипты локально с локальным хранилищем состояния для отладки и тестирования.

## Пайплайн CI/CD

В основном файле пайплайна, [terraform.yml](../.github/workflows/terraform.yml), реализованы действия для автоматизированного развертывания инфраструктуры. Пайплайн запускается как вручную (с указанием целевой среды и действия Terraform), так и пушу в дефолтную ветку репозитория (в этом случае запускается автоматический деплой в prod). В процессе развития проекта пайплайн можно доработать: например, завести отдельные ветки в репозитории для stage и prod, и запускать развертывание по мерджу в них.

Для развертывания используется сервисный аккаунт в Yandex Cloud. Он авторизуется при помощи механизма федерации: это позволяет полностью исключить хранение секретов и ключей в репозитории. Этот же механизм используется для получения эфемерного ключа доступа к объектному хранилищу. В результате, в репозитории GitHub хранится только несекретная конфигурация: идентификаторы облака, сервисного аккаунта и т.п.

Для удобства тестирования также добавлен файл [destroy.yml](../.github/workflows/destroy.yml): он позволяет запустить удаление развернутой инфраструктуры.
