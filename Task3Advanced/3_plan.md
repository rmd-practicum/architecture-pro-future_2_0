# План управления рисками

## Архитектурные

- Расхождение данных в переходный период
  - Технические решения: автоматическая сверка по расписанию; назначение одного источника истины на каждом этапе миграции; идемпотентность обработки
  - Управленческие подходы: миграция завершается, только если на протяжении переходного периода не выявлены расхождения сверх допустимого уровня
- Невыявленная скрытая логика в DWH, например, недокументированные хранимые процедуры; как следствие, искажение или потеря данных
  - Технические решения: анализ схемы БД, лога запросов
  - Управленческие подходы: назначение ответственного за инвентаризацию логики DWH; сверка правил расчетов с представителем бизнеса
- Утечка медицинских данных в аналитику из-за ошибки при публикации событий в медицинском контуре
  - Технические решения: медицинские данные не покидают медицинский контур и не отправляются через брокер сообщений
  - Управленческие подходы: привлечение сотрудников ИБ к анализу схем данных при их изменении
- Непредвиденное изменение схем передаваемых сервисами событий
  - Технические решения: реестр схем с валидацией; тестирование; DLQ для несовместимых сообщений и алертинг

## Организационные

- Нехватка компетенций команды при работе с новой архитектурой
  - Технические решения: применение managed-сервисов облака
  - Управленческие подходы: обучение сотрудников до начала миграции; привлечение внешних экспертов
- Сопротивление пользователей при переходе на новые инструменты аналитики
  - Управленческие подходы: обучение пользователей; документация
- Регуляторные риски при переносе медицинских данных в облако
  - Технические решения: шифрование и анонимизация данных; выделенная сеть
  - Управленческие подходы: выбор сертифицированных облачных сервисов; привлечение юристов к планированию миграции
- Повышенная нагрузка на сотрудников при миграции
  - Управленческие подходы: поэтапная миграция с обязательным пилотным проектом; автоматизация процессов; выделенная команда миграции

## Технологические

- Ограничения SQL Server 2008: старые версии протоколов, несовместимость с современными инструментами
  - Технические решения: проверка совместимости до начала миграции; промежуточная миграция на более новую версию SQL Server
- Баги в opensource-компонентах: несовместимость версий компонентов, сбои, слабая поддержка
  - Технические решения: отслеживание версий; обновление только через тестовые окружения; использование managed-сервисов там, где это возможно
  - Управленческие подходы: привлечение внешнего подрядчика для поддержки
- Отказ брокера событий, влекущий за собой простой всех процессов
  - Технические решения: managed Kafka, репликация в разных зонах доступности; паттерн transactional outbox при реализации сервисов; мониторинг
